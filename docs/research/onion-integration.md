# Onion Integration Research

This is a maintained summary of durable evidence, not a raw research log. The source baseline is Onion `v4.3.1-1`, commit `7dfc008b851398dcfe57819519efe5f958c77f65`. It was inspected from the official [Onion repository](https://github.com/OnionUI/Onion/tree/v4.3.1-1).

Status meanings:

- **Verified:** supported by the pinned source or official versioned documentation.
- **Partially verified:** source establishes a boundary, but device behavior or a complete path remains untested.
- **Hardware required:** cannot be accepted from source inspection alone.

| Area | Status | Durable finding and evidence |
| --- | --- | --- |
| Repository layout | Verified | `src/` builds Onion-native C applications; `static/build/` assembles SD-card runtime files; `static/configs/` contains default device/profile data; `static/packages/` contains App/Emu/RApp payloads; `third-party/`, `lib/`, and `include/` hold bundled dependencies and headers. Root `Makefile` defines the assembly. |
| Open-source boundary | Partially verified | Onion's repository is GPL-3.0. GameSwitcher, keymon, activity, boot UI, Tweaks, and packaging sources are present. Onion's own issue template identifies Miyoo MainUI as closed source and routes MainUI bugs elsewhere. Bundled cores, binaries, firmware-facing libraries, themes, and packages require their own notice audit before redistribution. |
| MainUI boundary | Verified | `static/build/.tmp_update/runtime.sh` launches `/mnt/SDCARD/miyoo/app/MainUI`, observes its exit, moves `/tmp/cmd_to_run.sh`, and then owns launch/post-processing. `src/common/system/state.h` detects MainUI as a process state. Sprout must integrate beside this boundary, not assume MainUI source is available. |
| Game launch scripts and arguments | Verified | GB and SNES package `launch.sh` scripts receive the ROM as `$1` and invoke RetroArch with their configured core. MainUI/runtime communicates the executable and quoted ROM through `.tmp_update/cmd_to_run.sh`; `runtime.sh` validates, normalizes, and executes it with the device environment. Sprout should produce or delegate this established launch contract rather than call a core blindly. |
| GameSwitcher lifecycle | Partially verified | `runtime.sh` uses `.runGameSwitcher`, launches the `gameSwitcher` binary, and removes the flag afterward. `src/gameSwitcher/gs_history.h` reads launch and ROM data and reconstructs a launch command. `keymon` controls the menu-button save/exit path. Actual save/resume/return behavior must be captured on a development card. |
| Guest Mode | Verified | `static/packages/App/Guest Mode/App/Guest_Mode/launch.sh` swaps `Saves/CurrentProfile` with `MainProfile` or `GuestProfile` and moves list/theme/time state. Official Guest Mode documentation says saves, states, remaps, history, favorites, GameSwitcher list, and play activity are separated. This is evidence for profile switching, not proof that arbitrary multi-profile switching is safe. |
| Saves and save states | Verified | RetroArch defaults point saves to `/mnt/SDCARD/Saves/CurrentProfile/saves` and states to `/mnt/SDCARD/Saves/CurrentProfile/states`; profile config also contains remaps, history, playlists, theme state, and ROM screenshots. Standalone emulators may use different paths and require per-system validation. |
| Activity Tracker | Verified | `src/playActivity/playActivityDB.h` stores the current database at `Saves/CurrentProfile/play_activity/play_activity_db.sqlite`; `runtime.sh` starts/stops tracking around recognized games. Legacy databases lived under `saves/playActivity.db`. Sprout must not double-count or corrupt this lifecycle. |
| SDL rendering | Partially verified | Onion native applications use SDL 1.2 libraries and a 640×480 hardware surface; `src/gameSwitcher/Makefile` and `src/bootScreen/` are useful baselines. Some code also uses Miyoo-specific `MI_GFX` paths. The viable Sprout renderer and performance budget require a device spike. |
| Input handling | Partially verified | `src/keymon/` monitors global shortcuts and process state; native UIs consume SDL events; low-level tools read `/dev/input/event0`. `src/common/system/keymap_sw.h` maps device keys for SDL. Final action mapping and coexistence with keymon require hardware tests. |
| Wi-Fi and startup services | Partially verified | `runtime.sh` starts networking before keymon and records MainUI Wi-Fi changes. `script/network/update_networking.sh` controls boot-time networking, time sync, SSH, FTP, SMB, Telnet, hotspot, and related state. Game launch may stop services for performance and restore their configured state afterward. Exact Sprout startup ownership is unresolved. |
| Safe boot and recovery | Hardware required | Onion documents holding `POWER` for 10+ seconds to escape an auto-resume boot loop. At boot, `runtime.sh` detects held `MENU` to clear `cmd_to_run.sh` and skip auto-resume. No evidence establishes the blueprint's proposed “hold B to stock Onion” behavior; Sprout needs a separate hardware-validated recovery design. |
| Cross-compilation toolchain | Partially verified | Root `Makefile` identifies `aemiii91/miyoomini-toolchain:latest`. Sprout pins its Linux AMD64 manifest `sha256:a8da1021449c80c0ccb75e263f1dfc75b5a004278fefa8a54151e55698a352f4`: GCC 8.3.0, `arm-linux-gnueabihf`, glibc 2.28, and Onion's Cortex-A7 hard-float flags. A complete ARM diagnostic links with static `libstdc++`/`libgcc` and target glibc, math, and pthread libraries. Device execution and SDL linkage remain unverified; see [ADR 0009](../decisions/0009-pinned-onion-toolchain.md). |
| License obligations | Partially verified | Onion is GPL-3.0 and Sprout is GPL-3.0. Source redistribution, modification notices, and corresponding source obligations apply to covered Onion-derived work. A release also needs an inventory of bundled cores, libraries, binaries, themes, fonts, and package assets; the repository-level GPL alone does not resolve their separate terms. |

## Immediate hardware validation

The next investigation should pin an actual development card to Onion `v4.3.1-1`, run the [isolated ARM device check](../development/onion-device-check.md), record the device and firmware revision, and verify one GB and one SNES flow through launch, menu-button exit, GameSwitcher resume, normal return, suspend, power loss, and the documented auto-resume escape. No Sprout launch-adapter design should be treated as complete before that evidence exists.
