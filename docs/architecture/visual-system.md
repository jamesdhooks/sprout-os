# Visual system

Sprout uses a warm illustrated storybook surface rather than a retro terminal
theme. This contract applies to the launcher and the built-in Arcade packages;
it is intentionally small enough to keep consistent on a 640×480 handheld.

## Surface language

- Full-screen environments use flat 2D watercolor and gouache textures, rounded
  silhouettes, visible paper grain, and soft natural light.
- Controls are cream translucent pills or cards with dark forest text. Coral
  and honey outlines identify focus; color is never the only state signal.
- Nunito SemiBold is the body face and Nunito ExtraBold is the display face.
  Reproducible SDL bitmap atlases and metrics are generated by
  `tools/generate-ui-font.py` from the bundled OFL-licensed variable font.
- Runtime packages use `sprout.label` for HUD and terminal-state copy so games
  share that type system instead of embedding one-off glyph tables.
- Profile selection is portrait plus name. Focus adds an outline, scale, gentle
  bob, and slight rotation without changing layout for other profiles.
- Text and controls require an opaque-enough backing panel when illustration
  detail would reduce contrast.

## Illustration boundaries

The SproutOS startup illustration is a product-level scene and is separate from
all game title screens. Each game title screen is a full-screen 4:3 illustration
whose baked title matches that game's visual theme. Game title art must not use
`Sprout` as a title prefix. The runtime overlays only dynamic controls.

Gameplay sprites, tiles, UI icons, backgrounds, and title art may retain
higher-resolution source detail. Runtime packages declare their own logical
resolution and asset dimensions; neither the engine nor this visual system
assumes that future games use 320×240 or 640×480 coordinates.

## Profile scenes

The neutral Garden Morning scene is used before a profile is active. Parents can
assign one reviewed built-in scene per profile from Profile Settings. References
are stable IDs rather than paths, so missing or retired assets can fall back to
Garden Morning safely. Custom profile portraits remain supported independently;
custom background import is not part of the current trust and storage boundary.

## Review

Every unique Windows-renderable view belongs in the deterministic visual capture
matrix described in [Visual validation](../development/visual-validation.md).
Artwork is accepted only after checking the 640×480 crop, title spelling,
control safe area, readability, and consistency with this contract.
